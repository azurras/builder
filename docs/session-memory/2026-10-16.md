## 2026-10-16 14:28 Central Daylight Time - Proxied cookies marked Secure after security review

**Project:** christopherbell-dev

- User asked for a security review of the website, with fixes for anything it found. [Plan](../implementation-plans/2026-10-16-13-45-christopherbell-dev-mark-proxied-cookies-secure.md).
- **Reviewed and found sound at `2528e37`:** the security filter chain and public matchers; JWT and browser-session authentication; role checks on every API controller; the site monitor's SSRF policy (public-only DNS answers, pinned address, HTTPS 443); shared-folder and music serving headers and path containment; redirect targets; inline JSON-LD escaping; rate limits; the production secret guard; live headers; actuator exposure. - **Observed, not fixed (not confirmed vulnerabilities):** anonymous joins can fill the survive camp to capacity, with only the 300/minute API limit slowing them; account survivors never expire from the camp; the CSRF cookie has no `SameSite`. Not covered: a full audit of every `innerHTML` sink, the federation inbound path (disabled in production), a line-by-line review of password reset, and dependency CVE scanning.
- **Verification:** RED, then GREEN `SurviveControllerTest`; `:website:build` with 2,138 tests and 0 failed; the [runtime report](../test-reports/2026-10-16-14-02-christopherbell-dev-mark-proxied-cookies-secure.md) with 10 of 10 cases across two isolated candidates; required CI; production readback showing `Secure` on both cookies and 403 without CSRF. No source issue; external closure does not apply.

## 2026-10-16 15:19 Central Daylight Time - Patched vulnerable dependencies and throttled reset mail after a deeper security review

**Project:** christopherbell-dev

- Deeper security review requested by the session that delivered PR #1544, aimed at what the 14:28 review did not cover. Reviewed at `main` `c702553`. [Plan](../implementation-plans/2026-10-16-14-35-christopherbell-dev-patch-vulnerable-dependencies-and-throttle-password-reset-ma.md).
- **HTML sinks, found clean:** every `innerHTML`, `insertAdjacentHTML` and `outerHTML` sink under `website/src/main/resources/static/js` (about 95 sinks in 19 files, 560 template interpolations traced). Post text, usernames, message bodies, report reasons, restaurant names, lunch voters and participants, music titles, artists and playlists, site monitor findings, notification text, shared-folder recycle paths and back-office fields all pass through `sanitize()`, `linkMentions()` (which escapes), `textContent` or `encodeURIComponent`. Survive, shared folder and command center build DOM nodes with no HTML sinks. Values interpolated raw are server-generated UUIDs, numbers, constants, `formatWhen` output, or the first character of a username, and `UsernameSanitizer` limits usernames to `[A-Za-z0-9._-]` at signup and update. Embed URLs are rebuilt from allowlisted hosts and still escaped.
- **Password reset:** sound in token entropy (32 bytes from `SecureRandom`), storage (SHA-256 hash only), one-hour expiry, single use (cleared on success), session revocation, a configured base URL (no Host header injection), a generic response and an `auth-mutations` limit of 20 a minute per client. **Fixed:** no per-account throttle, so anyone could flood a victim with reset mail (Resend is enabled in production) and keep replacing the token; now one link per account per five minutes. **Not fixed, with reason:** the existing-account path is slower (it saves and sends mail synchronously), but signup already answers "Account with given email or username already exists", so timing discloses nothing new.
- **Federation, found clean:** there is no inbound inbox or signature verification surface; inbound is only read-only discovery (WebFinger, NodeInfo, actor, outbox, followers, following). Outbound targets only operator-configured peers (at most 20), validated as HTTPS port 443 with no user info, query or fragment, resolved and pinned to global addresses (private, loopback, link-local, CGNAT, documentation and multicast ranges rejected), with redirects and proxies disabled and SNI plus hostname verification. Nothing fetches remote actors.
- **Dependencies:** GitHub's dependency graph sees only 11 manifest packages (no Gradle graph submission), so Dependabot had no alerts. An OSV query of all 146 resolved runtime artifacts found Jackson 3.1.5 and 2.21.5 (high-severity parsing DoS), Tomcat 11.0.24 (three critical advisories; the DIGEST and FORM ones do not apply because Spring Security handles authentication) and jsoup 1.22.2 (XML builder and `Cleaner` issues, both unreachable here). **Fixed:** Jackson 3.1.7 and 2.21.7, Tomcat 11.0.26, jsoup 1.23.2; OSV then returned no advisories. Spring Boot, Thymeleaf, springdoc 3.0.3, bucket4j 8.0.1, azure-data-tables 12.5.11, jjwt, OSHI and the rest had none.
- **Open observations decided:** `XSRF-TOKEN` without `SameSite` is not worth fixing: the double-submit header cannot be forged cross-origin and the authentication cookies are already `SameSite=Lax`. The two survive issues are confirmed and are game-design decisions for the user: one client can fill all 1,000 camp slots with anonymous joins in about 3.5 minutes under the 300-a-minute API limit (guests idle out after two hours, so refilling keeps the camp closed, and account players are locked out too), and account survivors count against capacity and never leave.
- **Verification and delivery:** RED, then GREEN `AccountServiceTest`; strict `:website:build` on `9b418a8` with 2,140 tests and 0 failed; the [runtime report](../test-reports/2026-10-16-14-53-christopherbell-dev-patch-vulnerable-dependencies-and-throttle-password-reset-ma.md) passed 7 of 7 cases. [PR #1545](https://github.com/azurras/christopherbell.dev/pull/1545) merged as `c292533` after green CI, production serves it, and a live reset request returns the generic 200. No source issue; external closure does not apply. Follow-ups: submit the Gradle dependency graph to GitHub; the user decides the survive capacity questions.
