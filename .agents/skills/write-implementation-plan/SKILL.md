# Write Implementation Plan

The implementation plan is the backbone of a change and its living record. It states what we want and what we do not, what we expect to change and how we will prove it, then records what actually changed along the way and how the work ended. Keep it true from planning through closure.

Choose only the requested mode:
- Plan: read [format and save command](references/plan.md).
- Update: use [living-plan updates](references/update.md) while implementing, when work diverges and at closure.
- Review: use [semantic readiness criteria](references/review.md).
- Validate: use [structural validation](references/validation.md).

The plan owns change-specific requirements, design, deviations, discoveries, decisions and their reasons. Dated session memory records the day's work and links to the plan instead of repeating it. Reuse an applicable existing plan and current Before-Edit Brief instead of recreating them.

Review/validation are read-only unless edits were requested. Planning-only scope ends at the published plan. Read existing content before intentional full replacement with --overwrite.

Follow AGENTS.md publication checkpoints using the [phase finalizer](../publish-builder-changes/references/phase-finalization.md).
